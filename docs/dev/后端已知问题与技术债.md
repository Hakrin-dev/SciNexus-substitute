## 一、高严重度(建议后端复工时第一批修)

### 1.1 SSE 对话兜底路径必然 NameError,流中途断裂

- **位置**:`backend/server/main.py:623`(`event_generator` 内),赋值点仅 `main.py:592`
- **现象**:`result` 变量只在 `AGENT_ENABLED=True 且 agent 调用成功` 分支被绑定;agent 关闭或抛异常走兜底分支后,`event_generator()` 首次执行 `result.get("run_id")` 即抛 `NameError`。此时 200 响应头已发出,客户端收到的是半途断流的 SSE。
- **影响**:**所有降级场景下的深度对话都是坏的**(无密钥、agent 崩溃、AGENT_ENABLED=False)。
- **修复**:except/else 分支补 `result = {}`;更稳妥的做法是在 try 成功后立即提取 `run_id = result.get("run_id")`,生成器内只引用普通局部变量。

### 1.2 同步 LLM/Agent 调用阻塞事件循环

- **位置**:`main.py:436、542、592、684`(async 端点内直调同步网关);`backend/server/agent_gateway.py:72`(`graph.invoke`)
- **现象**:`search_endpoint` / `chat_endpoint` / `chat_stream` / `translate_endpoint` 均为 `async def`,内部直接调用纯同步的 LangGraph 全流程(单次可达数十秒)。期间 uvicorn 单事件循环完全冻结,**所有并发请求(包括 `/api/health`)全部停摆**。
- **修复**(任选其一,按改动成本递增):
  1. 端点改普通 `def`,FastAPI 自动丢线程池;
  2. 保持 `async def`,`await asyncio.to_thread(_agent_chat_with_meta, ...)`;
  3. 根本解法:agent 层提供原生 async 接口(LangGraph `ainvoke`)。
- **连带**:`translate_stream`(main.py:692-696)先同步拿全文再"假流式",同一阻塞点。

### 1.3 sqlite 源加载失败时,回退数据会写穿真实库

- **位置**:`backend/agent/research_assistant/tools/store.py:51-55`(`_upsert` 全量 `DELETE FROM papers/venues`)+ `tools/data_source.py:332-338`
- **现象**:回退链(sqlite → json → server_mock → 内置兜底)按配置而非实际加载成功的源判定 `source_name`。`TOOL_DATA_SOURCE=sqlite` 时若 research.sqlite 短暂不可读/被锁,回退链取到 mock 的 13 篇演示论文,但仍以真实库路径构造 PaperStore → **DELETE 真实语料表并灌入演示论文**,静默数据破坏。
- **修复**:sqlite 源下 store 以只读方式接入(`PaperStore.open()`,基建已有但此处未用);回退到非 sqlite 源时强制 `db_path=":memory:"`。

### 1.4 CORS `allow_origins=["*"]` 与 `allow_credentials=True` 组合

- **位置**:`main.py:98-104`
- **现象**:Starlette 在 credentials 开启时会回显任意 Origin,等于允许任何网站携带凭据跨域调用全部 API(含文献库增删等写操作)。公网上线状态下风险实际存在。
- **修复**:`allow_origins` 收敛为前端域名白名单,环境变量注入。注:前端切同源 Route Handlers 后此风险对演示站自然消失,但后端独立部署时必须修。

## 二、中严重度

### 2.1 LangGraph 未设 recursion_limit,最坏情况整请求崩溃

- **位置**:`agent_gateway.py:72`、`research_assistant/supervisor.py:303,413-416`
- **现象**:全仓库无 `recursion_limit`,LangGraph 默认 25 superstep;图结构每个 agent 后必回 supervisor(每步耗 2),叠加 `max_retries=1`:autonomous_research 最坏 6 步 × 2 attempts × 2 + 初始/final = 26 > 25,弱模型下连续失败即 `GraphRecursionError`,前面已花的全部 LLM 调用作废。
- **修复**:`graph.invoke(initial, config={"recursion_limit": 2 * len(plan) * (max_retries + 1) + 4})`;或捕获 GraphRecursionError 转入 finalize 兜底。

### 2.2 OpenAI 客户端无 timeout / max_retries

- **位置**:`research_assistant/llm.py:92`
- **现象**:SDK 默认 timeout 600s、内置重试 2 次,串行管线上一次挂起可阻塞 30 分钟(Ollama 路径反而有 120s 保护,llm.py:215)。
- **修复**:`OpenAI(..., timeout=60, max_retries=1)`,config.py 暴露配置。

### 2.3 writer 无条件触发三阶段综述管线,成本放大一个数量级

- **位置**:`research_assistant/agents/writer.py:175-178`
- **现象**:无论综述还是论文草稿意图,都跑完 论断提取→聚类→成文→对比表≈8-12 次额外串行 LLM 调用;literature_review 全程约 21-25 次,零缓存。
- **修复**:writer.run 按 task_type 分流,仅综述意图进入 `build_literature_review`;为 complete/chat_text 加 prompt-hash 缓存。

### 2.4 文献库/收藏/通知为进程内可变全局态

- **位置**:`main.py:917、936-938、1030-1031`;`server/mock_data.py:80-117`
- **现象**:重启即失;多线程无锁;`new_id = f"lp{len+1}"` 删除后会与现存 id 碰撞导致误删两条;无法水平扩展。
- **修复**:短期 id 改 uuid;正确做法是入 sqlite(基建已有,加三张表即可)。

### 2.5 流式端点无限流 + 限流维度错误

- **位置**:`main.py:111(get_remote_address)、527-528 vs 579-580`
- **现象**:`/api/chat/stream`、`/api/translate/stream`(背后是最贵的 LLM 调用)**没有任何限流**;反代后 get_remote_address 拿到代理 IP,所有用户共享一个桶,易全局误伤 429;slowapi 内存存储单进程假设。
- **修复**:stream 端点补限流;启用 uvicorn `--proxy-headers` 或解析 X-Forwarded-For。

### 2.6 synthesis QA payload 无 token 预算

- **位置**:`research_assistant/agents/synthesis.py:179-185, 247-269`
- **现象**:qa_payload 为证据链全集每篇塞完整结构化分析(~1.3 万字符/篇),10 篇 ≈ 4 万 token,小模型直接失败、API 模型成本爆炸;同 PDF 还被重复解析两次。
- **修复**:精读篇数上限(≤3)+ 内容截断;parse_pdf 按 mtime 缓存。

### 2.7 综述对比表真实模式编号错位("mock 与真实同路径"的腐烂实锤)

- **位置**:`research_assistant/review.py:638-639 vs 675-709 vs 716-721`
- **现象**:`render_evidence` 把选中论文局部重编号 1..N,LLM 返回局部编号 rows,渲染却用全局编号查表——触发选样(>12 篇)时**属性值系统性安到错误论文上**;mock 路径恰好自洽所以测试发现不了。
- **修复**:render_evidence 保留全局编号或渲染侧按局部序号映射 `chosen[i-1]`;越界校验改用 `len(chosen)`。

### 2.8 回退链静默吞异常,降级不可观测

- **位置**:`main.py:52-54(agent 导入失败不记录!)、380-382`;`agent_gateway.py:221-222、405-406`;`data_source.py:282-296`;`supervisor.py:689-691`
- **现象**:多处 `except Exception: pass/continue`;langgraph 版本冲突等服务静默退化成 mock 模式,运维无感知。
- **修复**:每次降级必留 WARNING 及原因;import 失败处立即 logger.exception。

### 2.9 全局异常处理器泄露内部细节

- **位置**:`main.py:120-123`
- **现象**:500 响应带 `str(exc)` 与完整 path,可能暴露文件路径/SQL/上游 key 后缀。
- **修复**:对外通用文案 + request_id,详情进日志。

### 2.10 AGENT_ENABLED 时 `/api/papers` 静默丢弃筛选参数

- **位置**:`main.py:303-307`
- **现象**:ccf/year/keyword/sort_by 全部忽略但接口签名照常接受,前端表现"筛选项坏了"且无报错。
- **修复**:参数透传给网关(store.search 已有 filters 能力);不支持时显式返回警告字段。
