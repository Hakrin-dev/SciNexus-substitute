# 工具库 后端对接（MCP / 技能 / 插件）

> 配套：[PRD-工具库.md](../prd/PRD-工具库.md)；总览见 [后端对接总览.md](后端对接总览.md)

## 1. 现状

- 前端：`skills-board` / `mcp-guide` / `plugins-board` 为静态展示
- MCP 页有「我的服务器 / 配置说明」双标签页，无真实连接
- 后端**暂无** MCP / 技能 / 插件相关端点

## 2. 需新增端点

### MCP
- `GET    /api/mcp/servers`          我的 server 列表（含状态）
- `POST   /api/mcp/servers`          `{ name, transport(stdio|sse), command?, url?, env?, headers? }`
- `PUT/DELETE /api/mcp/servers/:id`
- `POST   /api/mcp/servers/:id/test` 连接测试（返回 tools 清单 / 错误）
- `GET    /api/mcp/servers/:id/tools` `tools/list` 缓存
- `PUT    /api/mcp/servers/:id/toggle` 启用 / 停用

### 技能
- `GET    /api/skills`                 市场 / 已安装
- `POST   /api/skills/:id/install`
- `DELETE /api/skills/:id/install`
- `PUT    /api/skills/:id/toggle`

### 插件
- `GET    /api/plugins`
- `PUT    /api/plugins/:id/toggle`
- `PUT    /api/plugins/:id/config`

## 3. 数据模型（草案）

```ts
McpServer { id, user_id, name, transport, command?, url?, env(加密), headers(加密), enabled, status, tools_count, last_error }
Skill    { id, name, description, category, installed, enabled }
Plugin   { id, name, enabled, config(json) }
```

## 4. 安全

- `env` / `headers` 明文只在创建时由前端提交，后端加密存储，前端不可读回明文
- MCP server 连接由**后端**发起（agent 侧），前端仅展示状态（避免前端直连暴露内网）

## 5. 与 agent 的联动（待 `backend/agent` 改造）

- 启用的 MCP server 工具，经 agent 的 tool registry 在对话中可用
- 技能 / 插件在 supervisor 路由时作为可选能力注入

## 6. 迁移步骤

1. 后端落地端点 + 加密存储
2. 前端 `mcp` / `skills` / `plugins` board 改读 hook（真实优先 + mock 保底）
3. 连接测试走后端（不在前端直连）
4. 「配置说明」页保留为「如何获取 URL / 命令」引导

## 7. 待定

- 技能 / 插件与前端组件（翻译 / 绘图）的映射
- 技能市场内容来源（官方内置 vs 用户上传）
