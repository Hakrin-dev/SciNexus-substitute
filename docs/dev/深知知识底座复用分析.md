# 深知知识底座能力复用分析

## 结论

深知的可复用成果不是某一个页面，而是一条稳定的能力边界：浏览器只访问本系统的同源 API；服务端负责调用知识底座、字段适配、超时/错误映射和有限重试；论文搜索、论文详情、关系图谱、全文状态和精读功能都建立在同一个 opaque `paperId` 契约上。

研枢原有实现已经接通了三条远程能力：

- `POST /api/retrieval/search`：论文检索；
- `GET /api/kg/paper?paperId=...`：论文详情；
- `GET /api/kg/graph?paperId=...&depth=...`：论文关系图谱。

本次复用重点落在 `lib/server/knowledge-base.ts`：统一服务端代理、限制最多一次自动重试、默认关闭本地演示数据回退、对外隐藏上游响应正文，并保留图谱 `provenance`。这样远程不可用时，页面呈现真实不可用状态，不会把本地样例误显示为知识底座结果。

## 深知项目的实现模式

深知将集成拆成四层：

1. `integrations/knowledge/client.py` 只处理 HTTP、timeout 和状态码；
2. `adapter.py` 将上游 snake_case/异构字段映射到领域契约；
3. `services/knowledge.py` 保持业务边界，不让页面依赖上游字段；
4. Web 端通过同源 BFF 访问后端，Mock 只能显式开启，不能在真实请求失败时自动启用。

稳定契约要求：ID 只作为 opaque string 使用；搜索结果 ID、详情 ID、图谱 rootId 必须一致；可选字段保留 `null`；计数未知时不能伪造为 `0`；未知图谱节点/边类型保留并采用默认展示；错误使用安全的字符串 code，不能透传 traceback、URL 或 secret。

## 研枢现有论文阅读链路

研枢的 `/papers/[id]` 阅读器由详情、全文、精读包和批注组成：

- 详情先请求远程论文元数据；
- 全文接口明确返回 `remote_metadata_only`，没有 PDF 时不会把摘要伪装成全文；
- 精读包以摘要分段，配置 LLM 时翻译，未配置时原文对照并标记为非翻译；
- 批注保存在当前用户与论文 ID 关联的表中；
- 关系图谱从同一 `paperId` 请求，前端按 References/Citations 展示。

因此，下一阶段应优先补齐真实 PDF/全文能力和图谱交互数据，而不是再复制一套本地论文模型。全文服务接入后，应让 `fulltext` 返回页码分块、来源和状态，精读包、证据引用和 AI 总结统一消费这些分块。

## 配置与验收边界

服务端配置 `RETRIEVAL_API_URL`、`RETRIEVAL_API_TOKEN` 和 timeout；不要使用 `NEXT_PUBLIC_` 前缀。正式环境默认 `RETRIEVAL_FALLBACK_LOCAL=false`，开发演示如需本地样例必须显式开启。验证至少覆盖：

- 搜索结果 ID 能打开详情；
- 详情 ID 等于图谱 rootId；
- 404、429、5xx、timeout 均转成安全错误；
- 上游失败时不会返回本地样例论文；
- PDF 不可用时全文状态明确为 metadata-only；
- 论文阅读页的批注、图谱和精读包继续使用同一个 opaque ID。
