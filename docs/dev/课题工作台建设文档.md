## 1. 总体架构(当前:纯前端 + mock 保底)

```
侧边栏「课题工作台」NavLink (/projects)
        │
        ▼
/projects/[id] —— 工作台壳 WorkbenchShell
   ├─ 项目头部:名称 / 状态 / 进度 / 视图 Tab(?view=)/ 助手栏开关
   ├─ 左栏 OutlineRail:紧凑大纲树(问题层级,常驻导航)
   ├─ 主工作区(按 ?view= 切换,或 AI 生成工作台):
   │    overview 概览仪表盘 │ outline 大纲树 │ thread 线程卡片流(默认)
   │    assets 资产表格     │ log 日志流    │ ProposalStudio(内联编辑,非弹窗)
   └─ 右侧 AssistantSidebar(可折叠,宽度≈中间栏略小):
        选中详情 + AI 建议 + Agent 运行情况 + 底部「AI 生成」入口
        (窄屏 <xl 以抽屉呈现)
        │
数据流:TanStack Query hooks(lib/api/services.ts)
        真实端点 /api/projects/{id}/... → 失败回退 lib/data/workbench.ts mock
```

关键约束:

- **TS 类型即契约**:`lib/data/workbench.ts` 导出的接口是前后端唯一事实来源;后端实现时字段命名向它对齐(延续仓库「前端优先」约定);
- 后端未上线时所有 hooks 走 mock 回退,组件不感知数据来源;
- AI 相关展示(AI 建议/匹配度/断点提示卡)在 M0 为静态演示数据,M2 接真实 Agent;
- 颜色一律走 `globals.css` 令牌,日/夜模式组件零改动。

## 4. 领域模型(TS 类型即契约)

完整定义见 [lib/data/workbench.ts](../../lib/data/workbench.ts),摘要:

```ts
type WorkbenchView = "overview" | "outline" | "thread" | "assets" | "log";

/* ── 大纲(Q/H/E/C 层级)────────────────────────── */
type OutlineKind = "question" | "hypothesis" | "evidence" | "conclusion" | "note";
type NodeStatus  = "open" | "supported" | "contested" | "done";

interface OutlineNode {
  id: string;                 // q1 / h1 / e3 …
  kind: OutlineKind;
  title: string;
  status: NodeStatus;
  detail?: string;            // 右栏展示的分析文字(aiNote 同)
  aiNote?: string;            // AI 分析(静态演示)
  assetRefs: string[];        // 关联资产 id
  children: OutlineNode[];
}

/* ── 研究线程(卡片流)──────────────────────────── */
type ThreadCardKind =
  | "question" | "literature" | "hypothesis" | "experiment"
  | "result" | "analysis" | "conclusion" | "next" | "hint";   // hint = AI 断点提示卡

interface ResearchThread { id: string; questionId: string; title: string; stage: string }

interface ThreadCard {
  id: string;
  threadId: string;
  kind: ThreadCardKind;
  title: string;
  summary: string;
  status: "todo" | "doing" | "done";
  assetRefs: string[];
  nodeRef?: string;           // 对应大纲节点
  aiGenerated?: boolean;
  createdAt: string;          // ISO
}

/* ── 资产(多维表格行)──────────────────────────── */
type AssetKind    = "paper" | "dataset" | "note" | "experiment";
type AssetStatus  = "unread" | "active" | "analyzed" | "archived";

interface WorkbenchAsset {
  id: string;
  kind: AssetKind;
  title: string;
  meta: string;               // 会议·年份 / 格式·大小 等
  questionIds: string[];      // ["q1"]
  hypothesisIds: string[];    // ["h1"]
  status: AssetStatus;
  tags: string[];
  updatedAt: string;
}

/* ── 日志(时间倒序)───────────────────────────── */
interface ActivityEntry {
  id: string;
  at: string;                 // ISO
  actor: "user" | "agent" | "system";
  type: "note" | "literature" | "data" | "task" | "summary";
  text: string;
  threadId?: string;
}

/* ── 概览聚合 + Agent 任务 ─────────────────────── */
interface WorkbenchOverview {
  focus:    { questionId: string; question: string; recentDocs: string[]; runningExperiments: string[] };
  blockers: { id: string; text: string }[];
  suggestions: { id: string; text: string }[];
}
interface AgentTask { id: string; agent: AgentName; label: string; state: "queued" | "running" | "done" }
type AgentName = "scout" | "librarian" | "synthesis" | "research_design"
               | "code_assistant" | "writer" | "critic";
```

关联规则:`assetRefs / questionIds / hypothesisIds / nodeRef` 均为弱引用(id 字符串);渲染时查表解析,**悬空引用静默忽略**(同综述管线零幽灵引用原则)。

## 5. 视图规格

### 5.1 项目头部(壳)

- 名称 + 状态徽章 + 简介 tagline;进度条 + 里程碑计数;
- 右上角仅保留**助手栏开关**(PanelRight 图标),其余操作(编辑/项目设置)保留在概览档案区,「AI 生成」入口移至助手栏底部;
- 视图 Tab 行:概览 / 大纲 / 线程 / 资产 / 日志,点击写 `?view=`。

### 5.2 左栏 OutlineRail(常驻)

- 仅渲染 `kind === "question"` 的顶层节点 + 子节点计数徽章;点击 → 跳大纲视图并选中该节点;
- 当前聚焦问题高亮(primary 色)。

### 5.3 概览 `?view=overview`

模块顺序:当前聚焦(进行中的问题/最近文档/运行中实验)→ 阻塞项 → AI 建议 → 项目档案(简介/里程碑/成员/链接,即原详情页内容迁移)。阻塞项与建议卡片点击可跳转对应视图。

### 5.4 大纲 `?view=outline`

- 完整树,节点缩进层级 + 折叠/展开;类型图标:Q(问题)/H(假设)/E(证据)/C(结论)/N(笔记);
- 状态样式:`supported` 绿 / `contested` 琥珀 / `open` 灰 / `done` primary;
- 点击节点 → 选中态 + 右栏联动;资产引用显示为数量徽章。

### 5.5 线程 `?view=thread`(默认)

- 按 `ResearchThread` 分节,垂直卡片流,时间正序;线程头显示问题标题与阶段;
- 卡片类型有区分图标/色调;`hint` 卡用琥珀底虚线边框突出;`aiGenerated` 卡带 Sparkles 标记;
- 点击卡片 → 右栏联动。

### 5.6 资产 `?view=assets`

- 表格列:标题(+meta)/ 类型 / 研究问题 / 相关假设 / 状态 / 更新时间;顶部搜索框 + 类型下拉筛选;
- 行点击 → 右栏联动;复用 `library-table` 的筛选与空态模式。

### 5.7 日志 `?view=log`

- 时间倒序条目流;actor 图标:user(UserRound)/ agent(Sparkles)/ system(Info);
- 顶部按类型(note/literature/data/task/summary)筛选 chips。

### 5.8 右侧 AI 助手栏 AssistantSidebar(可折叠)

- **折叠**:头部开关(壳右上角)与栏内收起按钮均可控制;展开宽度≈中间栏、略小(`1.05fr / 0.95fr`),收起后中间栏占满;窄屏(<xl)以右侧抽屉呈现;
- **内容自上而下**:选中详情(未选中时不占位)→ AI 建议(点击跳转视图)→ Agent 运行情况(纵向任务列表,替代原底部状态栏);
- **底部常驻「AI 生成」**:点击进入中间栏 ProposalStudio(选类型 → 生成进度 → 初稿内联编辑,不再弹窗);类型含开题报告 / 文献综述 / 组会PPT。

## 7. 后端开发规划(仅规范,本次不实施)

### 7.1 存储

沿用用户系统规划的 PostgreSQL(上线前的过渡期可用 SQLite 同构):

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| wb_projects | id uuid PK, user_id FK, name, tagline, status, progress, created_at | 现 `PROJECTS` 静态数据的持久化形态 |
| wb_outline_nodes | id uuid PK, project_id FK, parent_id NULL self-FK, kind varchar(12), title, status varchar(12), detail jsonb, sort int | 物化路径可选(path varchar)加速子树查询 |
| wb_threads | id PK, project_id FK, question_node_id FK, title, stage | 每研究问题一条 |
| wb_thread_cards | id PK, thread_id FK, kind varchar(12), title, summary, status, ai_generated bool, payload jsonb(assetRefs/nodeRef), created_at | hint 卡由断点检测任务写入 |
| wb_assets | id PK, project_id FK, kind, title, meta, status, tags jsonb, updated_at | 文献类可外链 library 记录 |
| wb_asset_links | asset_id FK, target_id, target_type(`node/thread`) | 多对多弱引用落库 |
| wb_activity_log | id PK, project_id FK, actor, type, text, thread_id NULL, created_at | Agent 写入与用户手动共用 |
| wb_agent_tasks | id PK, project_id FK, agent, label, state, updated_at | 底部状态栏数据源 |

索引:`wb_outline_nodes(project_id)`、`wb_thread_cards(thread_id, created_at)`、`wb_assets(project_id, updated_at DESC)`、`wb_activity_log(project_id, created_at DESC)`。

### 7.2 API 面(前缀 `/api/projects/{project_id}`,鉴权同用户系统 Bearer)

| 方法与路径 | 说明 | 对应 hook |
| --- | --- | --- |
| GET `/outline` | 整棵大纲树(嵌套返回) | useProjectOutline |
| PATCH `/outline/{node_id}` | 改标题/状态/排序/父子关系 | M1 编辑 |
| GET `/threads` · GET `/threads/{id}/cards` | 线程与卡片流 | useProjectThreads / useThreadCards |
| POST `/threads/{id}/cards` | 追加卡片(Agent 或用户) | — |
| GET `/assets?type=&q=` | 资产分页 | useWorkbenchAssets |
| POST/PATCH `/assets(/{id})` | 录入/更新 | M1 |
| GET `/activity?type=&limit=` | 日志倒序 | useWorkbenchActivity |
| GET `/overview` | 服务端聚合概览 | useWorkbenchOverview |
| GET `/tasks` · SSE `GET /tasks/stream` | Agent 任务与实时推送 | useAgentTasks |

SSE 复用 `/api/chat/stream` 的事件帧格式(`event/delta/meta`);AI 结果落库动作统一由 Supervisor 工作流末端的 persistence 步骤完成,不经前端转手。

### 8.3 写路径补全(2026-09)
