# PRD · 课题工作台

> 面向产品与设计。配套开发文档:[../dev/课题工作台建设文档.md](../dev/课题工作台建设文档.md)。
> 课题工作台 = 「科研 IDE」:以**研究大纲为骨架、研究线程为主工作区、仪表盘为入口、对话为交互层**的结构化工作台。当前版本仅落地前端(视图骨架 + mock 数据),后端能力见开发文档 §7 规划。

---

## 1. 背景与目标

### 1.1 问题

科研人员管理一个课题时,资产散落在文献管理器、网盘、笔记软件、聊天记录里;自由画布类工具又把「空间布局的维护责任」交给了用户——**而科研本身已经够复杂了**。

### 1.2 目标

| # | 目标 | 衡量 |
| --- | --- | --- |
| G1 | 一个课题的所有资产(文献/数据/笔记/实验)在同一工作台内可查、可关联 | 资产 100% 入库并可按研究问题检索 |
| G2 | 用户打开工作台即可回答「我现在该干什么」 | 首屏呈现当前聚焦 / 阻塞项 / AI 建议 |
| G3 | 组织工作由系统承担,用户只负责「消费」和「推进」 | 大纲节点、线程卡片、字段由 AI 自动填充,用户仅做确认与调整 |

### 1.3 非目标(本期不做)

- 多人实时协作编辑;
- 自由拓扑画布(明确不做,理由见背景);
- PDF 深度编辑/批注同步到原文件(阅读器复用现有 `/knowledge` 精读能力);
- 移动端专属布局(桌面优先,移动端可用即可)。

## 2. 角色与使用场景

个人科研者(研究生/独立研究者),典型一天:

1. **早上**:打开工作台 → 仪表盘显示「Q1 已 3 周无进展」「5 篇新文献与 H2 相关」→ 决定今天推进 Q1;
2. **白天**:进入 Q1 的研究线程 → 发现「假设 H1 缺乏数据支持」的断点提示 → 通过对话让 AI 检索补充文献 → 结果自动成为线程新卡片 + 大纲证据节点;
3. **晚上**:在日志里看到今天 AI 自动生成的摘要条目,补一条手动笔记后关机。

## 3. 功能需求

### 3.1 布局逻辑(全局)

经典左-中-右三栏 + 底栏:

```
┌─────────────────────────────────────────────────────────────┐
│ 项目头部:名称 / 状态 / 进度 / 视图 Tab 切换                    │
├──────────┬──────────────────────────────┬───────────────────┤
│ 左侧     │ 中间主工作区                  │ 右侧上下文面板      │
│ 大纲树   │ 默认:研究线程卡片流           │ 当前选中对象的:     │
│ (问题    │ (可切换:概览 / 大纲 /        │ - 详情             │
│ 层级)    │  资产 / 日志)                │ - 关联资产         │
│          │                              │ - AI 建议         │
├──────────┴──────────────────────────────┴───────────────────┤
│ 底部状态栏:Agent 任务状态 / 最近同步 / 提示                    │
└─────────────────────────────────────────────────────────────┘
```

- 所有视图共享同一套底层数据(资产 + 关系),只是呈现不同;
- 用户在任一视图的操作(改状态、拖拽排序)同步到其他视图;
- 视图切换通过 URL(`?view=`),可直接分享定位。

### 3.2 视图一:仪表盘 / 概览(入口)

- **模块**:当前聚焦(进行中的问题/实验)、进度概览(各线程阶段分布)、阻塞项(缺数据/待确认假设)、AI 建议(下一步读什么/做什么)、近期活动摘要;
- 完全由系统聚合生成,用户不手动维护;
- 现有项目管理信息(里程碑/成员/链接)并入本视图,作为「项目档案」区块保留。

### 3.3 视图二:研究大纲 / 树状骨架

- 形态:层级大纲(Workflowy 式),结构固定为 **研究问题 → 假设 → 证据 → 结论**,另允许笔记/方法论节点;
- 大纲天然对齐论文目录结构;每个节点点开后右栏显示详情与关联内容;
- AI 辅助:从文献/笔记提取「问题-假设-证据」链路生成大纲;新文献加入时提示「该证据可能支持 H1,建议插入此节点」;
- 用户操作:折叠展开、拖拽调整顺序、合并/删除节点。

### 3.4 视图三:研究线程 / 叙事流(主工作区默认视图)

- 形态:垂直卡片流,每张卡片是一个研究事件:

```
[研究问题] → [文献线索] → [假设] → [实验设计] → [数据结果] → [分析笔记] → [结论] → [下一步]
```

- 每个研究问题对应一条线程,线程间可互相引用;
- 卡片承载标题/摘要/状态/标签/关联资产;逻辑断点处(如假设缺乏数据支持)插入 AI 提示卡;
- Agent 完成任务后自动追加卡片(如「检索结果」「代码运行完成」);
- 卡片点击 → 右栏显示详情与 AI 分析。

### 3.5 视图四:资产数据库(表格)

- 形态:多维表格(Airtable 式),每行一个资产,字段:标题 / 类型 / 研究问题 / 状态 / 相关假设 / 日期 / 标签;
- 支持搜索、按类型筛选、按研究问题分组;
- AI 辅助:导入后自动填充元数据、自动归类到研究问题/假设、自然语言智能筛选(M2+)。

### 3.6 视图五:实验记录本 / 日志流

- 形态:时间倒序活动流,条目来源:手动笔记、导入文献、新增数据、Agent 任务输出、系统自动摘要;
- 支持按条目类型/日期筛选;AI 定期生成「每周研究简报」(M2+)。

### 3.7 交互层:AI 对话 + 右侧上下文面板

- 全局可唤起 AI 对话(复用 `/agents` 能力):自然语言下达任务 → 结果以卡片形式插入线程;
- 右侧上下文面板常驻:显示当前选中对象(节点/卡片/资产行)的详情、关联资产、AI 建议(如「这篇文章的核心方法与你的数据匹配度 85%」)与快捷指令(总结/翻译/找反驳证据);
- 底部状态栏:后台 Agent 工作流运行情况(下载中/代码运行中),随时感知但不干扰前台思考。

## 4. 交互细节

- 视图 Tab 切换不丢选中上下文;URL `?view=outline` 等可直接定位;
- 大纲节点 / 线程卡片的选中态高亮,右栏内容随之联动;未选中时右栏显示项目级 AI 概览建议;
- 空状态:新项目各视图提供引导文案(「从添加第一个研究问题开始」);
- 日/夜模式全视图适配,颜色一律走令牌。

## 5. 数据与 AI 依赖说明(给开发的衔接)

- 本期前端以 mock 数据驱动全部视图(样例沿用「研枢」项目),领域模型见开发文档 §4——**TS 类型即前后端契约**;
- 后端未上线前,AI 相关展示(建议/匹配度/提示卡)均为静态演示数据;
- 后端表结构、REST/SSE 端点、七 Agent 与卡片类型的映射关系,统一见开发文档 §7(仅规划,另行排期)。

## 6. 验收标准(摘要)

1. `/projects/{id}` 打开即工作台,五个视图 Tab 可切换且 URL 同步;
2. 概览含:当前聚焦、阻塞项、AI 建议、里程碑/成员/链接档案区;
3. 大纲树可折叠/展开/选中,节点类型(Q/H/E/C)有区分样式;选中联动右栏;
4. 线程卡片流含至少 8 种事件卡类型中的 5 种以上,含一张 AI 断点提示卡;
5. 资产表支持搜索 + 类型筛选,字段与契约一致;
6. 日志流支持按类型筛选,含 user/agent/system 三种来源条目;
7. `pnpm lint && pnpm build` 通过,日/夜模式截图无硬编码色。
